# 航旅智绘：航空旅客数字画像与 AIGC 智慧营销

第四届（2026）中国研究生企业管理创新大赛 · 数字技术应用专项 · 钻石命题2（东航研发—航旅数字画像）。项目名称暂定，正式提交前与报名系统统一。

围绕节假日旅游航线，构建 **需求识别 → 动态画像与分群 → 航线推荐 → 个性化内容 → 渠道与时机 → 人工审核 → 触达 → 效果评估** 的管理与技术闭环。

## 当前交付状态

这是可运行的项目框架和规则基线 Demo，尚不是企业生产系统。

| 能力 | 已实现 | 企业阶段待完成 |

## 立即运行

需要 Python 3.11+ 和现代浏览器；当前 Demo 仅使用 Python 标准库，无需下载依赖、API Key 或 Node.js。

```powershell
cd D:\GITHUB\Smart-Aviation-Marketing-Powering-Passenger-Profiling-with-AIGC
python -m app.server
```

打开 <http://127.0.0.1:8000>。在“可触达旅客”中选择画像，生成草稿，点击“内容审核通过”，再点击“模拟触达与评估”。

```bash
# macOS / Linux，在仓库根目录
python3 -m app.server

# 验证与复现
python -m unittest discover -s tests -v
python scripts/export_demo.py

# 更换端口或隔离演示数据
python -m app.server --port 8001 --database runtime/demo-session-2.sqlite3
```

演示数据库位于 `runtime/`，导出证据位于 `output/demo/`，均不提交 Git。固定数据截点为 **2026-09-27 00:00 UTC**，建议时段使用上海时区。画像是按窗口计算的动态方法，但当前没有实时采集。频控窗口固定，演示重启后仍保留模拟次数；新一轮演示请使用新的数据库路径。

## 推进顺序

1. 根据 [需求映射](docs/requirements.md) 与 [开发里程碑](docs/roadmap.md) 明确分工和验收证据。
2. 取得授权数据与业务访谈，按 [数据契约](docs/data-contracts.md) 构造特征和标签，执行时间切分验证。
3. 接入经过审批的大模型与知识源，替换 `TemplateContentProvider`；上线前完成身份认证、内容审核和触达授权。
4. 用真实实验补齐 [评估设计](docs/evaluation.md) 与 [商业测算](docs/business-case.md)，将证据写入 [报告骨架](docs/report/outline.md)。

## 参赛材料边界

来源是用户提供的命题PDF第2—3页及项目报告模板，详见需求映射。原始附件、真实旅客数据和团队身份资料未上传。模板明确要求封面有项目与团队名称，正文匿名评审，Word与PDF同时提交，文件命名 `命题2_团队名称`；正文建议10000—15000字。决赛Demo视频鼓励不超过5分钟、文件小于500M。该项目尚未生成最终Word/PDF报告。

评审标准附件二尚未逐项读取，本仓库不猜测评分权重；正式交付前按规程核对。

## 运行边界

服务只绑定 `127.0.0.1`，无企业身份认证，只用于可信本地演示。点击审核仅记录工作流状态，不验证审核人身份。当前SQLite适合单进程演示，企业投放需要独立权限系统、数据库、消息队列与反馈契约。网络操作必须继承已配置的 HTTPS 代理；没有代理时先询问，绝不输出密钥或绕过代理。
