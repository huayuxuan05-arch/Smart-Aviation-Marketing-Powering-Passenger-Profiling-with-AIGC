# 航旅智策——节假日航空智慧营销决策系统

面向航空公司节假日营销团队，将旅游需求、旅客兴趣、航空供给和内容生产连接起来，支持潜在客群识别、航线推荐、渠道选择、推送时机和活动复盘。

**当前交付：按五层架构重建的项目框架、实施任务和Word指南。平台、模型训练、RAG和真实AIGC调用尚未实现。** 已有公开数据是可追溯的研究基础；个人行为与营销反馈暂采用明确标注的合成数据方案。

先读 [项目实施指南](docs/project-plan.md)，或下载 [Word实施指南](deliverables/航旅智策_项目实施指南.docx)。

## 五层架构

| 层次 | 建设内容 | 设计入口 |
|---|---|---|
| 数据层 | 旅游搜索、航线、节假日、用户行为、营销反馈 | [数据契约](docs/data-contracts.md) |
| 算法层 | 需求预测、动态画像、航线推荐、营销策略优化 | [算法方案](docs/algorithms.md) |
| AIGC层 | RAG知识检索、个性化文案、视觉素材生成 | [RAG与生成](docs/aigc.md) |
| 应用层 | 可交互的航空智慧营销平台 | [页面与交互](docs/application.md) |
| 评估层 | 预测误差、推荐效果、营销反馈、模型对比 | [评估协议](docs/evaluation.md) |

总体关系见 [架构图](docs/architecture.md)。数据统一提供证据，算法输出决策，RAG为生成内容提供依据，平台组织人工操作，评估结果反馈到后续决策。

## 首个研究场景

- 假期：2025年国庆中秋，10月1—8日；历史节前决策截点为9月30日结束。
- 客源区域：上海；候选目的地：成都、三亚、昆明。上海—成都优先作为证据较完整的案例。
- 已核验：10个新增航空来源、36项指标、10组热门航线、10项东航航线供给记录，详见 [节假日航空数据](docs/research/china-holiday-aviation-data.md)。
- 尚缺：上海至三个目的地的完整逐日搜索、价格、预订量，以及真实个人行为和营销反馈。

机场总客流不等于上海出发的航线销量；少量新闻汇总不能冒充可训练的大数据样本。演示个人画像和反馈时，页面与导出均须标明合成数据。

## 落实顺序

新增[公开用户行为数据专项核验](docs/research/public-user-behavior-data.md)：飞猪商品/中转/素材、IntTravel、trivago 等 6 项新来源线索，区分可下载样例、需申请数据和暂不可用附件。IntTravel 已取得官方小样本；其匿名时间不能匹配真实节假日。现有 Booking.com 数据可用于独立推荐基准，不代表已取得项目场景的真实航空旅客日志。

1. 按数据契约整理节假日证据，补充可用日序列，建立统一日期与城市映射。
2. 建立可解释规则和历史基线，再按数据条件比较机器学习方法。
3. 建立带来源与有效期的知识库，设计RAG、文案、视觉与审核流程。
4. 依照页面规格实现Python后端与浏览器前端，打通一次完整活动流程。
5. 用固定时间切分和对照协议验证预测、推荐、内容与模拟反馈。

[任务路线](docs/roadmap.md)列出先后依赖与完成标准；[演示脚本](docs/demo-script.md)定义未来平台验收路径。

## 协作与验收

每项任务标明所属层、输入、输出、依赖及验收证据。提交前运行 `python scripts/validate_framework.py` 和 `python scripts/validate_public_data.py`。自动检查只验证文档、配置和数据一致性，不代表业务模型有效。

命题与报告要求见 [需求映射](docs/requirements.md)、[报告骨架](docs/report/outline.md)；管理与效益设计见 [商业方案](docs/business-case.md)。原始个人资料、凭据与未获许可的数据不得上传。
