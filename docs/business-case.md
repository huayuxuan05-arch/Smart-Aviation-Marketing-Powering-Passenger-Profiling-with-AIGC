当前采用公开信息与沙盒研究，不依赖企业真实旅客数据。按project-plan.md先做方法验证和财务情景；下文的真实订单、访谈和实验仅在将来具备条件时补充，不是当前框架门槛。相关企业痛点依据原始命题，具体规模和结果不能由合成数据代替。

## 诊断假设

根据命题背景（S1 p2），企业面临需求变化快、历史标签滞后、未购票意向难捕捉、渠道协同不足与内容同质化。它们是赛题提出的痛点；具体企业现状、规模和因果机制需要访谈/数据补充。

| 痛点 | 可检验假设 | 所需证据 | 管理动作 |
|---|---|---|---|
| 历史记录不足以识别未购票旅客 | 近期兴趣信号优于只用历史订单的基线 | 时点特征、后续订单、时间留出评估 | 动态画像成为运营决策输入 |
| 目的地与客源市场匹配不足 | 供给约束下兴趣推荐优于热门统一推送 | 区域/目的地需求、航线库存与随机实验 | 节假日航线与客群联动运营 |
| 内容同质化 | 经审核个性化内容提高有效响应 | 模板/LLM对照、审核质量、转化与投诉 | 内容工厂加人审，不扩大触达骚扰 |
| 渠道缺乏协同 | 统一授权与频控减少重复触达成本 | 渠道回执、退订、跨渠道接触次数 | 统一营销策略与实验治理 |

## 运营流程与责任

- 数据负责人：授权范围、数据口径、质量与撤回同步。
- 算法负责人：时点特征、意向与推荐验证、解释和漂移。
- 营销负责人：客群、预算、产品知识与活动目标。
- 内容审核负责人：事实、品牌、权益与生成质量。
- 渠道负责人：调度、幂等、送达反馈、统一频控。
- 实验负责人：预注册、统计和财务归因；避免以点击数代替收益。

以上是角色安排，不向匿名报告填入真实人员身份。活动审批、跨渠道协调和可验证ROI属于管理创新组成部分，不能只交一个聊天机器人。

## 财务测算口径（待填真实依据）

设N为固定期间符合授权/频控的目标用户数，p0/p1为对照/实验购票率，m为扣除变动成本后的单笔贡献毛利：

```text
增量订单 = N * (p1 - p0)
增量贡献 = 增量订单 * m
新增运营成本 = 模型生成 + 人工审核 + 增量渠道 + 优惠补贴 + 运维
期间净增益 = 增量贡献 - 新增运营成本
项目净收益 = 期间净增益 - 期间摊销的一次性研发/集成投入
ROI = (累计增量贡献 - 累计全部投入) / 累计全部投入
```

取消/退款、自然购票、渠道重叠、航线间替代和原营销被替换后的成本要保持一致口径。不把机票全额收入当利润，不以预测涨幅替代真实实验效果，不重复计算渠道成本。

| 输入 | 获取方式 | 当前状态 |
|---|---|---|
| 用户规模、基准购票率 | 企业授权统计，明确期间与分母 | 待获得 |
| 增量购票率与区间 | 真实随机实验 | 待验证 |
| 单笔贡献毛利 | 企业财务口径 | 待获得 |
| 模型/审核/渠道/优惠/运维成本 | 调用日志、工时、合同或发票依据 | 待获得 |
| 研发集成成本 | 工作量/人力/基础设施估计，写明假设 | 待团队测算 |

先做保守/基准/乐观情景和盈亏平衡，再估算回收期；没有数据时只展示模型与假设范围，不输出虚构收益金额。社会价值建议以服务可达性、减少无效打扰、数据安全与运营资源效率验证；碳减排必须有独立测量口径，不能由客座率改善直接推断。
