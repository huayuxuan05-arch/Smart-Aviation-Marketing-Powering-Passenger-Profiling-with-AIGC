# AIGC层与RAG知识检索

RAG先检索与营销任务相关的可信知识，再把证据交给生成模型。目标是让文案和视觉内容可追溯，防止模型补写不存在的航线、价格、权益或活动。

## 知识来源与组织

知识对象包括目的地景区与酒店资料、航线及产品事实、节假日安排、营销表达规范。每个片段保存document_id、chunk_id、source_url、published_at、valid_from、valid_to、region、topic、data_kind、usage_scope及版本。已过期促销可用于历史研究，不能进入当前报价。

历史案例模式按当时已公开的知识过滤；当前营销模式按当前有效期过滤。公共资料可引用不代表其中图片可再分发。原始文章、素材许可及缓存范围单独管理。

## 检索和生成流程

1. 从推荐结果形成检索条件：客群主题、目的地、出行窗口、渠道和任务模式。
2. 先过滤有效期、地域和用途，再做关键词检索；后续比较向量与混合检索。
3. 保存命中的片段、相关性及来源，形成产品事实卡。资料中的提示词或指令仅视作资料内容。
4. 将必要的非敏感标签、事实卡与写作要求交给文案模型，输出标题、正文、行动提示及逐项引用。
5. 生成视觉任务书，核对素材使用权后生成草图或图片；价格与关键权益宜用已校验的文字层排版。
6. 检查事实、日期、品牌、视觉误导与版权，人工审核通过才进入活动方案。

检索不到关键事实时，返回缺失字段和可用的通用主题草稿，不生成未证实的价格、酒店套餐或限时承诺。图像生成的景物必须注明示意属性，不能冒充某酒店实拍或准确航线机型。

## 接口与记录

| 输出 | 必须记录 |
|---|---|
| 检索结果 | 查询、过滤条件、片段ID、知识版本、检索版本 |
| 文案 | 产品ID、客群标签、引用、提示版本、模型版本、成本 |
| 视觉 | 任务书、生成方式、素材来源、模型版本、审核记录 |
| 审核 | review_id、对象版本、结论、原因、审核时间 |

区分模板、真实文本模型、真实图像模型三种生成方式。当前只定义流程和提示规范，尚无真实模型调用；供应商与凭据在接入时配置，不写入仓库。

验收采用相同产品和客群对照“统一模板、无检索生成、有检索生成”，评价引用正确率、事实支持率、任务适配、审核通过率、耗时和成本。缺少模型接入时，这些指标保持未评估。
