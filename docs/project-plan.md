# 航旅数字画像项目实施指南

中国研究生企业管理创新大赛数字技术应用专项

钻石命题2 东航研发航旅数字画像

版本 1.0　2026年9月27日

本指南用于安排参赛项目的研究、方案设计、验证和报告写作。项目要回答的核心问题是：如何利用节假日前的公开出行需求信号，发现潜在客群，将需求与航空产品匹配，并通过个性化内容和渠道协同形成可评估的营销方案。

**当前阶段先形成完整思路和实施框架。** 建议以一个节假日窗口和少量旅游航线作为试点，先做公开信息研究及规则基线，再决定是否开发原型。仓库中已有的合成数据演示可作参考，不作为本阶段必须继续开发的任务。

补充攻略提出企业无法提供真实数据。本计划因此采用“公开聚合信息用于市场洞察，沙盒数据用于个人画像与流程验证”的路线。公开搜索指数或内容热度不能直接还原具体旅客身份，也不能自动获得营销触达授权。

# 第一章 明确项目问题和研究范围

## 先选一个可以完成的场景

建议先确定一个节假日、一个主要出发区域和三至五个目的地。例如可用“国庆前的旅游航线营销”作为研究场景，但具体航线、节日年份、价格和供给信息必须从可核验资料中确定。已有演示航线及票价仅为虚构示例。

以“尚未购票但表现出出游兴趣的客群”为研究对象，分析传统历史订单和会员标签难以及时捕捉的需求变化。把市场洞察、产品匹配和营销运营放在同一链路中，避免只研究单独的画像工具或文案生成工具。

## 形成三个研究问题

1. 公开的目的地搜索与内容热度，能否提供比静态热门榜更及时的旅游需求信号。
2. 将地区、节日窗口、兴趣主题和预算情景结合，怎样匹配可售航空产品并解释推荐理由。
3. 按客群设计内容、渠道与时机，怎样减少无效打扰，并用一致口径验证价值。

## 写出一页项目定义

| 项目要素 | 具体写法 |
|---|---|
| 服务对象 | 航司节假日营销团队及产品运营团队 |
| 目标场景 | 指定节日 指定客源区域 指定目的地集合 |
| 核心决策 | 推什么产品 对什么客群 用什么内容 何时经何渠道 |
| 数据边界 | 公开聚合信号与沙盒数据 不依赖未获许可的个人轨迹 |
| 当前交付 | 研究方案 数据计划 技术路线 管理建议 验证设计 报告骨架 |

**交付物**：项目定义页、研究问题清单、需求流程图。**验收**：每个模块能说明服务哪项业务决策；范围足够小，团队可以在比赛期限内完成。

# 第二章 建立公开信息和沙盒数据路线

## 第一步 建立数据来源台账

优先选择可以访问、用途清楚且可引用的数据，不预设平台一定开放个人搜索、收藏或订单记录。旅游平台、内容社区和生活服务平台可以列入调研候选，但其个人行为不是默认可获取的数据。

| 信息类别 | 用途 | 记录要点 |
|---|---|---|
| 公开搜索指数或趋势 | 目的地需求变化 | 来源地区 时间粒度 查询词 授权条件 |
| 公开攻略和话题统计 | 兴趣主题与市场热点 | 样本范围 采样方法 去重规则 来源链接 |
| 公开旅游统计和行业资料 | 企业诊断与背景 | 发布时间 统计口径 原文页码 |
| 官方产品和航线信息 | 需求与供给匹配 | 查询日期 航线 价格条件 有效期 |
| 沙盒旅客和反馈数据 | 演示个人画像及闭环 | 生成规则 随机种子 假设与合成标识 |

可选来源尚未确认可得性。先用少量样本检验覆盖、时间跨度和可复现性；无法取得的信息应调整研究问题，不能编造平台用户行为。

## 第二步 分开两类数据

公开聚合数据形成“地区—时间—目的地—主题”的需求面板，用于群体洞察。沙盒数据生成虚拟旅客、兴趣事件、预算情景和授权状态，用于演示个人画像及活动流程。两者分别存储、分别标注；不能声称公开热度与某位虚拟旅客是实际身份映射。

## 第三步 检查质量并保存证据

统一城市、日期和主题词；记录缺失、重复、样本偏差与采集方式；保留来源及用途说明。每条报告结论关联来源ID。原始材料和不可公开数据留在受控目录，GitHub只保存代码、字典、合成样例及可公开的汇总。

**交付物**：来源台账、数据字典、需求面板、沙盒生成说明。**验收**：每张图都能回答数据来自哪里、时间是什么、能支持什么结论。

# 第三章 构建需求识别和旅客画像方法

## 先做市场需求识别

按地区和目的地汇总搜索、攻略与酒店关注等可用信号，观察节日前的变化。先采用标准化指数、环比或趋势规则，比较统一热门榜基线，再根据样本质量决定是否引入预测模型。不同平台指标口径不一致，应先标准化并做权重敏感性分析。

宏观信号描述的是市场兴趣，不能直接证明某人会买机票。如果没有个人真实标签，就不报告真实旅客购票预测准确率；可通过历史节日回测或趋势一致性验证市场层面的信号。

## 再设计沙盒画像标签

| 标签层 | 建议字段 | 使用边界 |
|---|---|---|
| 场景标签 | 出发地区 节日窗口 目的地 | 来源有记录 不推断真实身份 |
| 兴趣标签 | 海滨 美食 自然 文化等 | 公开主题归纳或沙盒事件 |
| 意向标签 | 兴趣新近性 近期频次 热点变化 | 明确计算窗口 不使用未来数据 |
| 价格情景 | 预算范围 价格关注比例 | 属于情景假设 不是实际消费能力 |
| 运营标签 | 渠道偏好 授权 频控 已购票 | 沙盒演示 实投需合法来源 |

可先定义高意向探索型、价格关注型、主题体验型等客群；客群是否有业务意义需要内容样例和运营访谈验证。标签必须可解释，不为显得复杂而堆叠维度。

## 动态更新怎么做

设定画像截点，取此前7天、14天或30天行为，近期信号权重较高。仓库示例采用30天窗口、7天指数衰减和规则意向分，这些参数仅是可替换基线。新增兴趣时重算标签，过期事件退出窗口；未来事件不能作为当前画像依据。

**交付物**：标签字典、更新公式、分群规则、三至五个客群样例、参数敏感性结果。**验收**：每个标签有来源、时间和业务用途；市场分析与个人沙盒结果分开陈述。

# 第四章 将需求与航空产品匹配

## 先筛可用产品 再排序

产品匹配不是只找热门目的地。先按出发区域、节日时间、航线存在性、可售条件和产品有效期筛选；有库存接口时再校验实时余位。没有实时库存时只能做规划推荐，不能宣称能够即时订票。

建议按目的地兴趣、主题适配、预算情景和供给约束排序。先做加权规则基线，再与“所有客群统一推热门航线”比较。排序理由应清楚说明哪些因素影响了结果。

## 推荐策略设计表

| 决策因素 | 如何使用 | 需要补充的依据 |
|---|---|---|
| 地区和时间 | 筛选可服务的旅行方案 | 航线及出行窗口信息 |
| 目的地兴趣 | 计算群体或沙盒画像匹配分 | 趋势面板或沙盒事件 |
| 主题偏好 | 调整产品表达和内容主题 | 主题词典及客群定义 |
| 预算情景 | 标出适配与不足 不隐性差异定价 | 价格来源及预算假设 |
| 供给和商业价值 | 在可售约束下合理排序 | 库存与毛利数据 未获得时不虚构 |

例如对一个“成都美食兴趣较高、预算情景为1000元”的虚拟旅客，生成相应航线推荐及理由。示例要说明身份、预算和事件均为合成；真实报价必须带查询时点和适用条件。

## 检查失败场景

检查无匹配航线、价格超过预算、促销过期、库存不足和目的地兴趣冲突。没有可用产品就返回原因，不让模型编造航班、舱位、酒店权益或优惠。

**交付物**：候选产品表、筛选约束、排序公式、推荐样例及失败案例。**验收**：每项推荐有可解释依据；信息来源和有效时间可追溯；不能购买的产品不会被标称实时可售。

# 第五章 设计AIGC文案和视觉内容

## 从客群到内容任务

先选择两至三个有差异的客群，并为同一航空产品设计内容对照。例如探索型侧重目的地体验，价格关注型突出清楚的价格条件，文化主题客群突出相关活动与景观。不能把“亲子”等假设标签当作真实个人身份。

在模型接入前，先整理内容输入和审核规则。输入包括经批准的客群标签、产品事实、渠道、语言和品牌要求；不输入实名、联系方式、原始个人事件或敏感属性。

## 生成和审核流程

1. 准备产品事实卡，列出航线、日期、价格条件、促销期限和可用权益及来源。
2. 生成标题、正文、视觉说明和事实引用；缺少关键事实时要求模型列出缺失项。
3. 核对产品事实、表达清晰度、客群适配、品牌一致和视觉版权。
4. 人工通过后才进入投放策略；生成失败或审核不通过就保留草稿。
5. 保存模型、提示、知识版本、调用成本和审核记录，方便复现与比较。

## 内容验证怎么做

| 对照对象 | 观察指标 | 合格依据 |
|---|---|---|
| 统一模板与个性化文案 | 相关性 清晰度 事实正确率 | 相同产品事实 人工盲评 |
| 模板视觉与模型视觉 | 品牌一致 信息误导 版权来源 | 同一任务 审核量表 |
| 不同提示版本 | 审核通过率 生成耗时 成本 | 保存输入输出及失败样例 |

当前仓库仅提供离线模板和原生SVG示例，尚未调用真实大模型。后续若只停留在方案阶段，应提交提示规范、样例和评估设计；若调用模型，必须如实标注实际提供者及输出来源。

**交付物**：产品事实卡、提示规范、文案与视觉样例、审核表、模板与AIGC对照。**验收**：没有编造价格、权益或保证性承诺；模板输出不被标成真实AIGC。

# 第六章 设计渠道推送和反馈闭环

## 选择渠道不等于获得联系方式

市场洞察可以指导渠道内容和广告计划，但公开平台热度不能直接提供个人营销授权。没有合法的个人触达条件时，只设计客群层面的渠道方案或使用沙盒模拟；不发送真实营销消息。

渠道方案可考虑企业自有App、邮件或平台合作广告等候选，分别评估可达性、内容形式、成本和反馈能力。候选不代表已开通渠道，也不代表已取得平台接口权限。

## 明确决策与执行的门槛

| 环节 | 决策规则 | 失败时怎么处理 |
|---|---|---|
| 授权 | 用途和渠道授权有效 | 不进入投放 |
| 时机 | 时区 偏好时段 节日前置期 静默时段 | 保留任务 调整时段 |
| 频控 | 跨渠道统一累计 联系上限清楚 | 暂停重复联系 |
| 内容 | 产品事实和人工审核通过 | 保留草稿 修订 |
| 执行 | 发送前复核 幂等键 失败重试边界 | 记录失败 不重复骚扰 |
| 反馈 | 送达 点击 购票 退订分开记录 | 不把点击当购票 |

当前演示采用授权门槛、7天2次频控及偏好小时规则，触达全是模拟。真实策略阈值应由企业业务及用户体验要求确定，不能把演示默认值写成官方规定。

## 建立活动状态和反馈记录

设计草稿、待审核、已审核、计划执行、已执行、已停止状态。每次操作记录活动ID、产品及内容版本、操作者、时间和结果。投放反馈关联实验分组及活动；订单归因窗口提前定义，避免跨渠道重复计算。

**交付物**：渠道选择矩阵、推送与频控策略、审核流程、反馈字段、模拟活动链路。**验收**：审核前不触达，撤回授权后停止，重复执行不会增加真实发送次数；无渠道授权则保持方案或模拟。

# 第七章 分层验证方案是否有效

## 先验证方法 再验证业务

验证应分为市场信号、算法方法、内容质量、工程流程和真实业务五层。沙盒可以证明流程可运行，不能证明真实购票率、客座率或满意度提升。

| 验证层 | 可以怎样做 | 能得出什么结论 |
|---|---|---|
| 市场信号 | 历史节日前后趋势 回测 热点一致性 | 公开信号是否及时稳定 |
| 画像与推荐 | 基线对照 时间切分 消融 参数敏感性 | 方法合理性及数据范围内性能 |
| 内容质量 | 模板与生成样例盲评 事实审核 | 文案与视觉质量及生成成本 |
| 工程流程 | 授权 审核 频控 撤回 并发测试 | 工作流和约束是否有效 |
| 真实业务 | 获授权后固定用户随机实验 | 实际增量效果及其不确定性 |

没有真实购票标签时，用代理任务评价市场信号，或明确标注为合成验证。不把由人为设定概率产生的转化数据当作真实预测准确率。

## 真实实验应如何设计

若后续取得试点条件，在符合授权和频控的用户中固定随机分组。对照组采用现有策略，实验组采用新方案；提前确定转化分母、订单窗口、最小可接受提升、样本量和停止规则。报告转化率差及置信区间，同时监测投诉、退订和错误报价。

客座率要用指定航线和班次的实际载客与可用座位计算。满意度要用有效问卷或企业指标。不能由点击率直接推导这两项结果。

## 每项结论建立证据台账

记录结论、来源、时间、方法、代码或模型版本、数据范围、是否可公开以及对应报告章节。将“命题痛点”“研究假设”“模拟结果”“真实实验结果”分别标记。

**交付物**：验证计划、对照与消融表、评估量表、证据台账。**验收**：每个结果明确证据等级；没有真实实验时，只陈述可行性与待验证价值。

# 第八章 形成管理建议和经济效益模型

## 将技术模块转化为管理动作

建议建立节日客群运营机制、产品知识与内容审核机制、跨渠道统一频控机制，以及以实验和收益为依据的活动复盘机制。为每项建议明确负责人角色、输入、审批、周期和指标，解释如何改变现有决策流程。

组织协同也是项目内容。数据角色维护口径，营销角色确定客群和产品，内容角色审核事实，渠道角色执行策略，评估角色负责归因和财务测算。匿名报告可写角色，不出现成员、学校或导师身份。

## 用贡献毛利而非票价计算收益

设N为期间内有效目标用户数，p0与p1为对照和实验购票率，m为单笔贡献毛利。建议用以下口径建立可填写的测算表。

| 指标 | 计算或取值方法 |
|---|---|
| 增量订单 | N乘以实验与对照购票率之差 |
| 增量贡献 | 增量订单乘以单笔贡献毛利 |
| 新增运营成本 | 模型调用 人审 渠道 优惠 运维 |
| 期间净增益 | 增量贡献减新增运营成本 |
| 项目净收益 | 净增益再扣期间研发和集成摊销 |
| 投资回报率 | 累计净收益除以累计全部投入 |

未获得业务数据时，用清楚标注的保守、基准、乐观情景展示测算逻辑；参数写明来源或假设。不虚构增收金额，不把全部票价当利润，不重复计入渠道成本。检查退款、自然购票和航线间替代的影响。

## 社会价值怎么写

围绕减少无效打扰、提升服务可达性、避免数字排斥、保护数据安全和改善资源配置提出可检验指标。碳减排若没有独立测算依据，就不写确定数值。创新点通过基线与流程差异论证，避免未经检索的首创宣称。

**交付物**：管理建议表、责任流程、财务输入表、情景与敏感性分析、社会价值指标。**验收**：建议对应诊断证据，收益与成本口径一致。
