# 航旅智策——节假日航空智慧营销决策系统

项目实施指南

五层架构与落地任务　版本2.0　2026年10月8日

本项目面向航空公司节假日营销团队，围绕潜在客群识别、旅游航线推荐、渠道选择、推送时机和个性化内容生产，设计可交互的航空智慧营销决策系统。

本指南说明怎样从数据准备推进到算法、RAG、平台与评估，供团队分工、开发和参赛报告写作使用。目标架构由数据层、算法层、AIGC层、应用层和评估层组成；当前完成框架和公开数据调研，模型及平台按照本指南实施。

## 本阶段交付

项目定义、五层设计、数据契约、算法与评估协议、页面交互、接口规划、任务路线和报告骨架。当前已有中国节假日公开聚合证据；真实用户行为、营销反馈及完整航线日序列尚需补齐，个人流程可用合成数据验证。

# 第一章 确定业务场景

## 服务对象与决策

服务对象为航空公司节假日营销、产品运营和内容审核人员。一次活动需要确定目标区域与客群、候选航线、预算、渠道、时机和内容，并保留决策证据及反馈。

首个案例采用2025年国庆中秋，出行窗口为10月1日至8日，客源区域为上海，候选目的地为成都、三亚和昆明。以9月30日结束为历史节前决策截点，节后发布的实绩仅用于评价，不进入节前特征或知识。

## 场景落实

| 要素 | 当前安排 |
|---|---|
| 首选演示航线 | 上海—成都，已有节前热门名单与东航供给证据 |
| 比较候选 | 上海—三亚、上海—昆明，分别标明证据和缺口 |
| 研究粒度 | 区域、目的地、节假日；有日序列后扩展到日 |
| 个人画像 | 使用合成事件，或未来获授权的匿名行为 |
| 内容任务 | 目的地主题、航线规划、清楚的来源和条件 |
| 当前执行 | 方案设计与后续模拟活动，不发送真实营销消息 |

## 需要回答的问题

1. 节前搜索和旅游兴趣能否补充传统热门航线信息，帮助选择候选目的地。
2. 动态偏好与供给约束怎样影响航线排序，如何让营销人员理解推荐理由。
3. RAG是否减少内容事实错误，个性化文案与视觉是否更适合目标客群。
4. 不同渠道、时间与预算方案怎样比较，哪些结论需要真实订单或随机试验。

本章交付一页场景定义和研究问题。验收时检查每个功能是否服务上述决策；没有证据的价格、库存和个人偏好保持未知。

# 第二章 五层架构与信息流

## 各层职责

| 层次 | 建设内容 | 交付结果 |
|---|---|---|
| 数据层 | 旅游搜索 航线 节假日 用户行为 营销反馈 | 数据版本 质量与来源台账 |
| 算法层 | 需求预测 动态画像 航线推荐 营销策略优化 | 预测 画像 候选与策略解释 |
| AIGC层 | RAG检索 个性化文案 视觉生成 | 引用 内容版本 审核记录 |
| 应用层 | 可交互航空智慧营销平台 | 场景操作 活动方案 模拟反馈 |
| 评估层 | 预测误差 推荐效果 营销反馈 模型比较 | 对照结果 失败案例 成本与限制 |

## 一次活动如何流转

数据层先说明哪些信息在决策截点前可用。算法据此产生市场需求判断和画像快照，筛选航线并给出渠道、预算与时机方案。AIGC层检索相关知识，生成带来源的文案和视觉素材。平台负责展示、调整、审核和模拟活动；评估层记录结果并为下一轮调整提供依据。

每条输出保留场景ID、数据版本、计算截点、来源ID和数据属性。模型结果另带模型版本，内容另带知识和提示版本，活动另带活动ID。数据更新后，旧结果不能在界面继续显示为最新。

## 技术实现路线

采用Python模块化后端和浏览器前端，先按业务模块组织单一服务。结构化表、知识文档和图片分开管理；模型供应商与检索器使用可替换接口。具体框架及部署方式在实施时选择，当前不预设某付费产品已接入。

仓库backend、frontend、knowledge和experiments目录提供实施约定。它们是开发入口，尚不是可启动的系统。完整架构关系见docs/architecture.md。

# 第三章 建设数据层

## 五类数据的准备顺序

| 数据 | 优先准备什么 | 主要缺口 |
|---|---|---|
| 节假日 | 官方日期 天数 调休与对照窗口 | 新增年份需重新核验 |
| 航线 | 城市对 机场 运力计划 价格时点 | 完整日班次 座位 历史价格 |
| 旅游搜索 | 目的地 主题 地域 指数和观察日 | 上海地域逐日搜索趋势 |
| 用户行为 | 搜索 浏览 收藏 时间和主题 | 企业真实个人事件未取得 |
| 营销反馈 | 曝光 点击 购票 退订 活动关联 | 真实活动和归因标签未取得 |

先整理已有2025国庆中秋事实，再补可导出的日序列。个人行为和反馈若使用合成数据，要定义生成规则、随机种子及事件关系，不将它们标成平台真实用户。

## 时间与粒度

每条记录保留来源、发表日、获取日、可用时点、统计期、地域、单位和数据属性。票价必须区分查询日与出行日、含税与否、最低价与均价、单程与往返。历史回测按当时可用的信息过滤。

机场吞吐量不能替代城市对销量，票数不等于独立人数，平台热度不等于航空需求人数。节日8天合计不得均分成8条假日序列；缺失保存为空，零只表示实际观测到零。

## 质量验收

1. 统一地点、日期和单位，原值与转换结果同时保留。
2. 检查来源有效、重复、缺失、统计口径及使用范围。
3. 将公开聚合、授权个人和合成数据分开存储与展示。
4. 生成覆盖率和缺口清单，再决定可以启用哪些模型。

数据负责人交付数据字典、来源版本、质量报告和合成规范。现有36项航空指标用于研究事实，数量和粒度尚不足以训练可信日预测模型。

# 第四章 建设算法层

## 四个任务与基线

| 任务 | 首个可解释方案 | 升级条件 |
|---|---|---|
| 需求预测 | 历史同类节日 滞后值 移动平均 | 多节日同口径日序列和目标 |
| 动态画像 | 7天与30天窗口 时间衰减 标签快照 | 带时间的行为事件与验证依据 |
| 航线推荐 | 先筛约束 再按兴趣主题预算排序 | 曝光 选择或相关性标签 |
| 策略优化 | 固定方案与规则方案比较 | 成本 响应概率 预算约束可估计 |

需求预测必须先定义预测什么：搜索指数、机场客流或城市对预订量分别建模。缺少真实目标时只展示趋势分析，不报告航空销量预测准确率。具备样本后比较线性模型与梯度提升树，清洗和标准化只在训练集拟合。

## 动态画像与推荐

标签覆盖目的地、兴趣主题、价格关注、行为新近性和渠道偏好。保存计算时点、事件依据、置信度与有效期。冷启动返回群体先验和信息不足，长期无事件降低置信度，未来事件不进入当前画像。

推荐先核对出发区域、旅行窗口、航线存在性和产品有效期，再排序并说明分项理由。无实时库存时输出规划候选；没有价格就标记未知。无法匹配航线时给出原因，不生成不存在的产品。

## 渠道与时机

策略同时考虑预算、渠道容量、授权、静默时段、频控和内容审核。第一阶段采用规则与情景成本；数据足够时再比较约束优化。点击概率不等于营销增量，模拟最优结果不代表真实投资回报。

交付物为目标定义、特征字典、标签快照、推荐解释、策略约束和基线配置。验收关注可复现、时间正确、失败可解释，不预设某种复杂模型一定更好。

# 第五章 建设RAG和AIGC层

## 先形成可检索知识

知识库收集目的地景区与酒店信息、航线产品事实、假日安排和营销规范。每个片段保存来源、发表及有效日期、地域主题、用途和版本。历史案例只用当时可用的知识，当前营销只用当前有效的产品条件。

检索先做可解释关键词基线，再比较向量及混合方式。保存命中片段与来源，汇成产品事实卡。来自网页的指令仅是资料内容，不能控制生成流程。资料可阅读不代表其中图片已获再分发许可。

## 内容生产步骤

1. 按客群、目的地、旅行窗口、渠道和任务模式构造检索条件。
2. 过滤地域、日期与用途，再检索；缺失价格或权益则列出缺项。
3. 输入必要的非敏感标签和事实卡，生成标题、正文、行动提示与引用。
4. 编写视觉任务书，核对素材权利，再生成图像或草图；关键价格用已校验文字排版。
5. 检查事实、时效、品牌、误导和版权，经人工审核进入活动方案。

## 输出验收

| 对象 | 检查要求 |
|---|---|
| 检索 | 相关片段可定位 来源和有效期明确 |
| 文案 | 每项可验证事实有依据 缺失不编造 |
| 视觉 | 示意图不冒充实拍 数字权益准确 |
| 版本 | 记录模型 提示 知识 成本和审核 |

统一模板、无检索生成与RAG生成使用相同任务对照，评估事实支持率、引用正确率和人工适配评分。模型未接入时如实展示模板模式，不能称为真实大模型成果。

# 第六章 建设交互应用层

## 七个工作页面

| 页面 | 操作 | 主要结果 |
|---|---|---|
| 节假日需求看板 | 选假期 客源 目的地 截点 | 来源 覆盖 观察与预测 |
| 客群画像 | 查看客群或合成旅客 | 标签 时间变化 置信度 |
| 航线推荐 | 设日期与预算情景 | 候选 约束 理由 缺失项 |
| 营销策略 | 调整渠道 时机 预算 | 方案比较 成本假设 |
| AIGC内容工坊 | 检索 生成 修改 审核 | 引用 文案 视觉 版本 |
| 活动与反馈 | 保存 审核 模拟 停止 | 状态 事件 反馈漏斗 |
| 评估与模型比较 | 选实验和对照 | 误差 推荐质量 样本与限制 |

## 一次完整交互

进入国庆中秋场景，查看上海及目的地数据覆盖，选择合成客群，取得航线规划候选，设置渠道与发送窗口，检索知识生成内容，审核后模拟活动，最后查看反馈与评估。修改上游条件时，下游结果标记为待重算。

## 状态与异常

活动状态为草稿、待审核、已审核、模拟执行、完成或停止。已审核内容再次修改必须重新审核；重复执行请求保持幂等。界面标明公开聚合或合成属性，导出时保留来源与时间。

没有日数据不造曲线，没有标签不填准确率，没有库存显示规划推荐，知识过期时解释原因。模型失败可保存草稿并提供重试，不隐藏失败。真正上线前实现角色权限和审计；当前框架不提供公网服务。

交付物为页面、接口、状态机与端到端演示。验收同时走通正常路径和无航线、无价格、空画像、知识缺失等失败路径。

# 第七章 建设评估层

## 指标选择

| 评估对象 | 指标 | 需要什么证据 |
|---|---|---|
| 预测误差 | MAE RMSE WAPE | 同粒度真实目标与时间切分 |
| 推荐效果 | Recall@K NDCG@K 覆盖率 | 相关性标签 候选集 用户或客群 |
| 营销反馈 | 点击 转化 退订 成本 | 分母 去重 订单归因窗口 |
| 画像质量 | 覆盖 稳定 更新及时性 | 事件时间与标签依据 |
| RAG与内容 | 引用 事实支持 盲评 | 固定知识 任务和评分规则 |
| 模型对比 | 效果 耗时 成本 | 同数据 同切分 同预算 |

MAE是绝对误差均值，RMSE是平方误差均值的平方根。WAPE以实际值绝对值之和为分母，分母为零时不计算。没有相关性标签时只报告推荐覆盖和约束，不计算虚构的NDCG。

## 对照与切分

按时间划分训练、验证和测试，先在验证集选参数，再报告测试集结果。画像和知识检索同样受截点约束。逐步比较静态与动态画像、热门与规则推荐、固定与优化策略、模板与RAG内容，移除单一因素做消融。

点击率统一采用去重点击人数除以有效曝光人数；转化分母和归因窗口提前指定。退款、重复订单、跨渠道归因分别处理，不把点击当购票。合成反馈只验证程序和评估流程。

## 记录与结论

每次实验登记数据、模型、知识版本、种子、样本量、切分、配置、失败案例、耗时和成本。公开聚合研究、合成实验、真实观察与随机试验分开报告。缺少样本时填未评估，不填零。

模型误差下降不能直接证明营销增收。没有真实业务对照时，只陈述方法表现与可行性，不写客座率或转化提升比例。

# 第八章 按依赖安排建设任务

## 六阶段路线

| 阶段 | 工作重点 | 完成门槛 |
|---|---|---|
| 1 数据 | 场景 来源 日序列 合成规范 | 日期 粒度 来源和覆盖明确 |
| 2 算法 | 预测目标 画像 推荐 策略基线 | 可解释 可复现 无时间泄漏 |
| 3 AIGC | 知识 检索 文案 视觉 审核 | 事实引用 版本和失败处理 |
| 4 应用 | 后端 七页面 活动模拟 | 完整交互 状态清楚 可导出 |
| 5 评估 | 对照 消融 盲评 结果登记 | 同口径比较与限制说明 |
| 6 报告 | 诊断 管理 财务 展示 | 证据一致 匿名和格式检查 |

建议按六周组织上述阶段，团队可按实际期限调整，这不是官方赛程。日序列不足时先完成研究事实和规则基线；真实模型训练、学习排序和渠道试投都有独立数据依赖。

## 分工和协作

数据角色负责来源、质量与数据版本；算法角色负责目标、基线和解释；知识内容角色负责知识、提示与审核；前后端角色负责交互与状态；评估角色统一切分和指标；统筹角色负责命题、报告和商业论证。人数少时可兼任，但内容审核与结果复核应保留独立视角。

GitHub任务写明所属层、输入、输出、前置任务、负责角色和完成证据。合并前检查链接、数据引用、配置及必要功能；Word源变化后重新生成并逐页检查。

首批优先完成D01数据字典、D02样本条件、M01预测定义、M02画像推荐、G01事实检索、A01页面契约和E01评估协议。任务编号及详细门槛见docs/roadmap.md。

# 第九章 管理价值与参赛报告

## 将模块对应到管理问题

数据与需求看板减少重复整理来源，动态画像帮助跟踪偏好变化，推荐和策略把供给与预算纳入决策，RAG与审核让内容有据可查，评估记录帮助活动复盘。上述价值均需用时间、质量、覆盖或真实业务数据检验。

## 财务口径

增量贡献为增量订单乘单笔贡献毛利，扣除生成、人审、渠道、优惠和运维成本后得到净增益。计算项目回报时纳入研发和集成投入，说明退款及自然购票处理。票价不等于利润，合成转化不等于企业收益。

数据不足时使用保守、基准和乐观情景，逐项说明假设并做敏感性分析。组织责任包括数据维护、策略审批、内容审核、渠道运营与独立评估，报告按角色描述。

## 对应官方报告结构

| 报告部分 | 项目材料 |
|---|---|
| 项目基本信息 | 正式名称 场景 摘要 核心证据 |
