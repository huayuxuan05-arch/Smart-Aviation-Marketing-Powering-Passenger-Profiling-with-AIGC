# 应用层：航空营销操作流程

网站首页 http://127.0.0.1:8765/ 提供两个入口，个人旅客页面位于 /personal/，营销人员页面位于 /marketing/。由server.py提供静态资源及对应接口。

| 页面 | 已实现操作 |
| --- | --- |
| 旅行方案（默认） | 全量旅客列表、去返历史参考、逐日活动、住宿、预算、参数调整、AI说明及导出 |
| 活动总览 | 查看热点、区域及活动，新建和管理活动 |
| 需求洞察 | 调整假期、区域、目的地、客群及门槛，计算未保存预览 |
| 潜客与画像 | 查看证据、兴趣变化，筛选、冻结名单和导出 CSV |
| 航线与策略 | 比较最多3个兴趣候选，查看当次计划预算、推荐理由及覆盖对照 |
| 创意工坊 | 本地 Qwen 生成、编辑、SVG 导出、审核及待审核素材删除 |
| 渠道触达 | 分开检查素材覆盖、业务条件、逐人执行资格，明确暂缓原因并导出 |
| 效果复盘 | 回放未来七天行为、更新画像、查看独立历史漏斗 |

主要接口：GET /api/health、GET /api/mkt/meta、GET/POST /api/mkt/insights、POST /api/mkt/traveler，以及 /api/mkt/campaigns 下的活动、画像、名单、素材、触达和评估操作。历史漏斗位于 GET /api/mkt/historical。

状态由 runtime/marketing.sqlite3 保存。活动可删除、恢复；删除当前活动后退出并清除前端选中状态。素材修改、名单版本变化需重新审核。同一旅客同一情景日跨活动最多一次模拟触达，重复请求不会伪造外部消息、点击或订单。

画像弹窗的行程意图卡可回查计划和预算原始记录。GET活动响应中的execution字段动态重算本地资格；执行时在频控账本同一写事务中重新核验素材、原始历史候选、截至模拟发送时刻的退订和频次。旧版名单缺少新证据结构时保留可读，但需重新创建后执行。本地资格不代表真实可售或真实渠道授权。

服务只监听本机，校验同源写请求及静态资源路径。不提供公网认证和真实渠道连接。部署、操作和验收命令见[应用使用说明](../航旅智策应用/README.md)。

2026-10-14旅行规划更新：默认首页为“旅行方案”，独立服务全量10,000名模拟旅客，不按营销名单限额或退订状态删减规划对象。逐人提供去返历史航线参考、逐日活动、住宿区域与条件、预算拆分、备选建议和行前清单；支持3/4/5/7天、节奏、日期及全程预算调整，JSON及可打印HTML导出。本地Qwen可在既有事实范围内细化可编辑旅行说明。

默认国庆、2024-09-30截点的逐人核验：10,000/10,000有旅行方案及去返航线参考，569人的去程目标日有历史直飞记录，9,984人保留关注首选方向。其他日期原记录不改日期；两段航线不宣称已核验联程；苏州显示真实机场城市与地面接驳。全部历史参考不等于实际可售产品，非机票费用是情景假设。

旅行需求问卷位于 `/marketing/survey.html`，已在原文件上压缩为30题，全部单选或多选，复测只需10题。每次选择一个年份和关注假期，再勾选城市、具体景点、日期时段和预算档位；其他假期可另填。保留近7天、8—30天、31—90天的回忆窗口。随机研究编号自动生成，复测导入原答卷即可沿用，无需手写。按独立response_id去重并保留历史快照，预算档位不转换成精确金额；旧V1答卷按原版本读取。真实答卷不自动关联模拟user_id。

旅行接口：GET /api/mkt/travel-plans（分页、搜索及全量核验），GET/POST /api/mkt/travel-plans/{user_id}（规划参数），POST /api/mkt/travel-plans/{user_id}/explain（本地模型细化）。独立问卷不上传答卷；回收后在研究者设备导入、查看画像变化并下载全部快照。

2026-10-15独立入口更新：网站首页 `/` 为“个性化旅游定制”入口选择页。个人旅客从 `/personal/` 填写自己的出发地、目的地、日期、同行、兴趣和预算，生成、保存及导出自己的旅行方案；支持保存偏好、查看偏好更新及用本地Qwen细化说明。个人端不读取模拟旅客画像，偏好和方案存放独立的 `runtime/personal.sqlite3`，不同浏览器会话分别访问自己的方案。

营销人员从 `/marketing/#trips` 使用全量旅客规划、需求洞察和活动管理，界面统一使用“节假日航空智慧决策系统”，包括浏览器标题、侧栏和顶部导航，并标注营销人员端。两端顶部均提供“返回首页”，返回入口选择页。两端均不提供直接切换至另一身份的链接，返回首页后可重新选择入口。各页面移除底部重复的品牌文字，顶部品牌名称及图标保留。旧 `/#trips` 等工作区链接会转到对应营销页；活动、审核和原始数据保留。

个人接口使用 `/api/personal/bootstrap`、`/state`、`/preferences`、`/plans`、`/plans/{id}`、`/plans/{id}/explain`。HttpOnly、SameSite=Strict的独立cookie关联随机会话，数据库仅保存token摘要，方案读取和AI细化均先检查所有权。偏好写入使用版本检查，防止旧标签页覆盖新偏好；保存旧方案不会重写原快照。该本地Demo未增加营销人员账号登录体系。

2026-10-15文字需求协商：个人页支持“规划一次旅行”和“调整当前方案”。自然语言先成为独立草稿，显示字段及原文依据；首次会话不继承未确认的核心默认值，已保存偏好明确标注沿用。仅有“国庆”不推定年份与日期，“两人总预算”不直接平摊，往返航空金额不作单程上限。含糊、冲突、未支持城市或天数需澄清。未确定预算可以明确留空。不同目的地的景点清单会清空并显示在草稿中。

调用既有规划器生成未保存预览，反馈调整比较原方案与草稿的同行节奏、目的地、情景总额和预算差额；费用未变化时如实显示。确认需勾选核对并提交，服务在同一事务中检查会话、偏好版本、草稿版本、24小时有效期及未处理状态，保存偏好快照、新方案和确认依据。确认只能执行一次；放弃、未确认或校验失败不改变已保存方案。针对过时历史方案的反馈不能修改当前偏好。

接口：`POST /api/personal/assistant/drafts`创建草稿，`POST /api/personal/assistant/drafts/{id}/clarify`补充待确认字段，`/confirm`确认并保存，`/cancel`放弃。草稿位于本机personal.sqlite3独立表，按浏览器会话隔离；不写入模拟画像或营销活动。后端专项测试覆盖澄清、数字与日期核验、确认前只读、会话隔离、过期/旧版本/重复确认边界及未接模型时禁止启动推理；浏览器专项覆盖完整交互及390px布局。模型提取协议仅以模拟返回验证，当前部署不启动模型。

旅游规划的详细行程和预算组装在travel_planner.compose_plan共享；营销端继续使用既有模拟动态模型，个人端使用当次主动填写的偏好。航班日期、历史报价和未核验联程状态按原记录展示。

验收：本机完整后端83项通过；entry_browser_check.cjs覆盖双入口、个人生成/保存/导出、不同浏览器会话隔离、偏好版本、手机布局与旧链接。设置AEROLENS_TEST_LOCAL_AI=1可额外实际调用本地模型。所有验收写入独立runtime/tmp目录，不使用生产个人方案库。

## 当前航班与原页面集成

个人与营销端共用现有航班区域，未新增页面或导航。个人方案生成后后台匹配当前航班，支持人数及航程条件。查询和预算预览不修改偏好或既有方案；确认后保存新方案与parent_plan_id、query_id、查询时间和人数。每名成人预算由实际组报价均摊后确定，非机票部分仍为估算。旧航班数据不会在无结果或网络错误时回填。后台保留错误记录，页面仅展示有效报价。


## 界面规范与个人方案管理

个人旅客可在历史方案列表中逐项确认删除；取消不修改记录，删除仅作用于当前浏览器所属方案。删除当前方案后打开另一份保留方案，全部删除后显示空态；旅行偏好及其版本保留。推理期间删除方案时，延迟返回的结果不能重新保存被删除方案。

个人端主要模块及逐日行程提供键盘可操作的展开与收起。进入或刷新时默认收起，同一页面重绘保留手动展开状态，不读取旧的会话展开记录；生成AI建议时自动展开建议区。32px圆形SVG箭头区分展开、收起与悬停，整行支持鼠标和键盘操作。首页、个人端与营销端八个页面统一移除操作解释、小字提示和重复说明，保留实际日期、报价、费用项目、执行状态及错误。字体统一为英文 Times New Roman，中文 Microsoft YaHei，其他设备使用对应中文后备字体。
