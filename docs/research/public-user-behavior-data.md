核验日期：2026-10-08。联网使用用户已配置的 HTTPS 代理。本文聚焦用户级搜索、浏览、点击、购买和出行序列，区分发布说明、文件清单与实际下载结果。未登录他人账号，未提交数据申请，未将个人事件明细上传仓库。

## P14：飞猪 UBF，最值得优先申请

官方说明给出的行为统计期为 **2019-06-03 至 2021-06-03**，对象为脱敏后的旅游商品交互，涉及机票、酒店、旅行团等平台产品。

- `user_item_behavior_history.csv`：用户 ID、商品 ID、行为类型、时间戳；行为枚举为 `clk`（点击）、`fav`（收藏）、`cart`（加购）、`pay`（购买）。
- `user_profile.csv`：用户 ID、年龄编码、性别编码、职业编码、常居城市编码、标签编码。
- `item_profile.csv`：商品 ID、类目编码、城市编码、标签编码。

适合在同一数据集内连接用户、商品与历史事件，构造最近活跃时间、访问频次、兴趣类目变化、收藏/加购信号与购买标签。没有核验到搜索关键词、机票实际金额或真实航线名称，`pay` 事件不能直接当作消费金额。

**获取情况与问题：**

1. 官方说明要求点击申请、填写资料并接受条款，通过后下载；说明提及七日内审核，这不是本项目对实际审核时长的承诺。本次未代填身份或提交申请。
2. 本次匿名详情接口返回两份文件：用户属性约 168.7 MB、商品属性约 4.6 MB，**没有列出行为主表**。因此需要登录后确认主表是否另行授权或已经下架，不能保证申请后一定能取得。
3. 官方说明存在规模冲突：正文表格写 22,516,238 次交互，英文详情另有 224,542,018；用户数和商品数也有不同版本。本项目不采用其中任一版本作为实际下载行数。
4. 正文称 CC BY-NC 4.0，接口许可标签与链接存在不一致。使用前保存当前适用的数据条款，并确认参赛展示、衍生结果及再分发范围；不将其视为无限制商用数据。

**节假日适配：**时间范围可能支持历史假期前后的行为研究，但需要取得主表后确认时间戳是否保留真实日期、时区及抽样覆盖。城市和类目为编码，没有映射表时不能声称某条记录来自上海或对应三亚机票。2019—2021 年包含疫情期间，迁移到当前航空需求时需单独评估。

来源：[官方数据页](https://tianchi.aliyun.com/dataset/113649)，详情接口与文件清单的核验摘要见本文配套台账。

## P15：飞猪中转方案，有价格，但并非航空航线

官方说明统计期为 **2022-08-16 至 2022-09-17**。行为表含用户 ID、OD 查询 ID、中转方案 ID、行为类型和时间戳，枚举为 `browsing`、`purchasing`、`reference`；保留原始语义，不把 `reference` 擅自映射成收藏。

方案属性包括出发/到达城市编码、两段出发/到达时间、两段价格、总时长和总价格。关键字段是 **First Train ID / Second Train ID**，说明这是火车中转方案，适合作为跨交通方式选择与价格/时间偏好的辅助基准，不能标成中国航空订票日志。

文件清单列出：行为表 1,484,201,975 字节、用户表 45,923,468 字节、方案表 710,349,152 字节。本次下载接口明确返回未登录，未下载三张表。说明中的“48.8M million”有明显单位歧义，未采用为可信用户数；许可标签与链接不一致，仍需核对。

来源：[官方数据页](https://tianchi.aliyun.com/dataset/140721)。

## P16：飞猪营销素材，方向贴合，暂不列为已可用

官方说明列出 **2022-09-03 至 2022-12-03** 的素材行为：用户 ID、素材 ID、上下文 ID、`browsing/click/pay`、时间戳，以及素材类别、图片标签 ID、文本标签 ID。即使未来文件完整，这些标签也不等于原始图片或文案。

当前说明仍写完整数据公开申请进行中。文件清单中 `user_behavior_item_sample.csv` 与 `item_profile.csv` 均仅 **4 字节**，且名称与正文的 creative 表名不一致；另有用户属性文件。不能据此声称已获得可训练的营销曝光/点击/购买日志。正文“62M million”也有单位歧义，不引用为实际规模。页面许可字段标为 CC BY-NC-SA 4.0。

该项保留为后续关注，不作为现阶段 AIGC 素材效果评估的主要依赖。即便取得观察性点击日志，也不能直接证明新生成素材带来的因果提升。

来源：[官方数据页](https://tianchi.aliyun.com/dataset/151847)。

## P17：IntTravel，中国出行序列，已取得官方小样本

[作者仓库](https://github.com/AMAP-ML/IntTravel)、[Hugging Face 数据页](https://huggingface.co/datasets/GD-ML/IntTravel_dataset)、[原始论文](https://arxiv.org/html/2602.11664v1)相互指向。发布方说明数据来自中国地图、导航和实时交通服务，包含出行相关交互；不能将全部交互称为旅游消费或航空出行。

官方报告完整规模为约 41 亿次交互、1.63 亿用户、729 万 POI。此为**发布方规模说明**，本次没有下载完整库，也没有独立核对全量行数。

本次实际检查了 GitHub 的三个小文件（扩展名为 csv，实际为制表符分隔）：

| 文件 | 实际数据行数 | 已核验结构 |
|---|---:|---|
| user_action.csv | 137 | 9 列；4 个用户、82 个交互 POI；行为码 0—3 |
| user_profile.csv | 4 | 用户 ID 与 6 个匿名特征 |
| poi_info.csv | 112 | POI、热度、地理块、类别、行政区编码；5 列，无坐标 |

这是发布方提供的小型结构样例，适合检查读取和关联逻辑，**不足以训练或评估有代表性的模型**，也不能依据样例推断全量分布。仅原始文件保存在本地忽略目录，仓库提交字段、计数和哈希。

重要边界：

- 论文明确说明时间戳经过处理，仅保留相对顺序；不能转成真实年月日后匹配中国假期。
- 用户特征名称和值、行为名称、地点类别与行政区均匿名化；不能擅自解释为真实年龄、职业、上海、景区或机场。
- 论文所述二维坐标也不是经纬度；当前 Hugging Face 数据卡明确说明 POI 暂不含坐标，小样本亦如此。
- 数据卡称交互分为 100 份，本次仓库清单仅列出 99 个 `interaction_*.csv`（缺 82 号）。完整摄取前需要检查版本完整性。
- 本次读取的作者仓库与数据卡未见明确数据许可证；公开下载不等于获得商业使用或再分发许可。正式训练与交付前应确认条款。

适合验证相对时间序列、匿名兴趣变化、下一 POI 与多任务推荐；不能用它直接检验“2025 年国庆上海—三亚机票需求”。

## P18：trivago，搜索浏览过程最清晰的补充候选

官方 RecSys 2019 页面确认任务为酒店搜索会话推荐。[发布方基线代码](https://github.com/trivago/recsys-challenge-2019-benchmarks/blob/master/src/data_handling/feature_building.py)实际使用：

`user_id, session_id, timestamp, step, action_type, reference, impressions, prices`

代码列出的行为包括搜索酒店、查看图片/信息/评分/优惠及 `clickout item`。后者是跳转点击，不是已付款订单。`impressions` 与 `prices` 可用于展示列表排序和价格相关分析，但价格偏好仍需模型验证，不能仅凭价格字段直接确定。

官方要求注册账号并接受条款后下载。旧下载域名 `recsys.trivago.cloud` 本次访问失败，未取得真实数据文件；基线工具生成的 example data 不能冒充真实日志。代码 MIT 许可也不能自动用作数据许可。

来源：[官方比赛页](https://www.recsyschallenge.com/2019/)、[官方代码仓库](https://github.com/trivago/recsys-challenge-2019-benchmarks)。

## P19 与已有 P08：意向预测、预订序列的补充

**精品旅行服务成单预测：**找到[参赛者第二名方案](https://github.com/Bifzivkar/Boutique-Travel-Services-Predict)，说明有用户基本信息、浏览行为及发生时间、历史订单、待预测标签和评论五类表，适合购买意向识别。该来源是参赛者对赛题的说明，不是数据发布方的再授权。仓库 `data` 目录实际只有结构说明，没有原始 CSV；未核验原比赛下载仍可用，因此列为待恢复来源的线索。不要为了取数转向来源不明的旅客身份或酒店入住记录。

**Booking.com 多目的地预订（P08）：**此前已检查 1,166,835 条训练记录，含用户、行程、匿名目的地、入住/离店、设备和渠道编码。可作为当前目的地序列算法的离线基准。它没有搜索/点击过程，入住时间不等于预订发生时间，也没有消费金额。适用非商业及其他发布方限制，详见[第二轮核验](project-related-data-second-round.md)。

## 本项目的接入顺序

1. **先处理飞猪 UBF 获取条件。**登录官方页，确认主行为表、时间处理方式、城市/类目映射和适用许可；没有主表时，单靠画像表无法训练行为模型。
2. **用已有文件推进结构与基线。**IntTravel 小样本只验证事件读取和关联；Booking.com 完整训练集用于目的地序列实验，结果明确标为境外匿名住宿预订基准。
3. **行为与节假日证据分别评估。**保留各数据集自己的用户命名空间；不跨平台拼接相同数字 ID，不为匿名城市强行匹配真实航线。节假日预测继续收集真实日期可对齐的中国搜索/航线/价格数据。
4. **统一事件字段但保留来源语义。**建议保留 `dataset_id, user_key, session_key, item_key, event_type_raw, event_type_normalized, event_time_raw, time_semantics, region_key, provenance`；不存在的字段留空，不伪造关键词、停留时长、票价或曝光。
5. **按可用任务评价。**有购买标签才评估购买预测；有候选展示列表才评估对应排序；搜索活跃时段只能辅助推送时机，最优营销发送时间与增量转化仍需授权实验或明确标注的模拟反馈。

配套机器可读台账：[user-behavior-datasets-20261008.json](../../data/public/user-behavior-datasets-20261008.json)。本轮没有训练模型、调用营销渠道或发送申请。
