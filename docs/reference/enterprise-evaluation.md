# 验证与证据计划

## 证据等级

| 等级 | 当前有哪些 | 可支持的结论 |
|---|---|---|
| 需求来源 | 用户提供赛题、报告模板 | 场景和交付要求 |
| 工程验证 | 单元/HTTP测试、合成数据、演示工作台 | 流程可运行、关键约束有效 |
| 数据验证 | 暂无授权数据 | 获得数据后才能讨论画像真实性和预测性能 |
| 业务实验 | 暂无真实投放 | 获得随机实验和业务指标后才能讨论增量收益 |

当前随机分组转化率使用人工概率生成，任何差值均不可写成企业营销提升成果。

## 算法对照设计

| 任务 | 基线 | 候选提升方案（待实现） | 评估 |
|---|---|---|---|
| 意向识别 | 事件次数、窗口衰减规则 | 逻辑回归→树模型，具备标签后再考虑序列模型 | PR-AUC、ROC-AUC、Brier/校准、Precision@预算 |
| 动态分群 | 高意向/探索/已购票规则 | 可解释聚类、稳定性与运营可用性复核 | 稳定性、群体规模、业务差异、授权覆盖 |
| 推荐 | 同出发地热门航线、当前兴趣+预算排序 | 内容相似度、学习排序，真实可售约束 | Recall@K、NDCG@K、覆盖率、不可售推荐率 |
| 渠道/时间 | 已授权渠道优先级与偏好小时 | 基于历史响应/成本的策略，小样本先不用复杂强化学习 | 增量转化、成本、送达、退订、频控违规 |
| AIGC | 当前静态模板 | 有依据的LLM文案与视觉生成 | 事实正确、相关性、品牌一致、审核通过、时延、单条成本 |

时间切分在真实业务上执行：特征截止于as_of，购票标签在as_of后；测试集不参与阈值选择。报告必须写明样本量、标签窗口、类不平衡、缺失、重复与数据授权，不从合成数据拟合“高精度”成果。

## 消融与稳健性

分别移除兴趣衰减、预算因素、个性化内容和渠道选择，检验每个模块贡献。按春节/国庆/暑期、区域、客群分层；比较价格变化、库存稀缺、数据缺失与模型漂移。所有阈值（目前0.5、7天衰减、7天2次频控）都应做敏感性分析，并记录业务约束。

## 真实随机实验（待授权）

1. 从授权且符合频控的旅客中建立样本，按用户固定随机分组，避免同一人跨渠道污染。
2. 对照组使用企业现有策略；实验组使用新方案。实验开始前登记主要指标、归因窗口、观察时长、护栏、样本量、停止规则；不不断查看结果后提前宣称成功。
3. 主要指标建议为固定归因窗口内的购票率，分母使用分配用户数（ITT），同时报告送达样本分析。退改/退款按预登记规则处理。
4. 报告转化率绝对差（百分点）、相对差（对照为0时不计算）、95%置信区间与样本量；显著性之外评估是否达到实际业务价值。多组比较需调整方法。
5. 客座率以目标航线与班次为单位：实际载客/可用座位；不能从点击率推导。满意度需要有效问卷与样本偏差说明。成本包括生成、审核、渠道、优惠与运维。
6. 样本量粗略设计可用两比例比较的近似式 `n/组 ≈ 2*(z_alpha/2+z_power)^2*p_bar*(1-p_bar)/delta^2`；实际应依据基准率、最小可接受提升、聚类/重复用户与企业统计方案复核。
